# Prem Oracle 1.9, Slice 2: "Matchday comes alive" (plan only)

Status: plan, no code. Written 25 Nov 2026 on `feature/v1.9-slice1`, after Slice 1 (f7184cc).
File references are to that commit.

## What exists today (facts the plan builds on)

**"Confirmed lock" does not exist yet.** Lock is a clock comparison made at read time and never recorded:
- Picks: `matchLocked` (worker/src/logic.js:4) and `savePick`'s 403 (worker.js:2092).
- Reveal: `fixtureLockMs` (logic.js:709).
- Slate: `slateLockAt` / `slateIsLocked` (logic.js:350–373).
- `SLATE_STATUSES` lists "locked" and "settled", but nothing writes them. `lockedAt` is stamped at publish time.

**The only scheduler is a 15-minute cron** (`*/15`, wrangler.toml:6). That is too coarse for "1–2 minutes after lock".

**Push infrastructure is good and reusable:**
- `sendPush(…, {collapseId, expiration})` in apns.js.
- The `NOTIFY_QUEUE` queue plus the `NotifyLedger` Durable Object: SQLite claims, leases, 5 attempts, a budget, and a dropped-log.
- The consumer re-checks before sending.

**Preferences:** the only one is a per-competition mute list on `push:<uid>` (`POST /notification-prefs`).
- No "Deadline reminders" switch exists. Today reminders are on whenever iOS permission is granted, and muted per competition (Profile shows that only for players in 2 or more competitions).

**Reveal data already refuses before lock.** `buildRoundReveal`'s gate (logic.js:741) never serialises a pick before `serverNow >= lockMs`. `/state?period` includes picks only for members (`viewerIsMember`, worker.js:2398), with `private, no-store`.

**Tap routing:** `po:{v:1,f,l}` → `readNotificationRoute` → `openNotificationTarget`. A payload with an unknown `v` already falls back to My Picks, so old builds degrade safely.

**Movement:** the season ▲/▼ is computed against "minus the last fixture" (`computeTableWithMovement`). The weekly ▲/▼ is client-side (`weeklyMovement`, app.js:4298). Nothing is stored.

## P1: Batched reveal alert

**Slot:** every fixture sharing one `lockAt` (in practice, one kick-off time) across all published slates.

**1. Plan (existing 15-minute cron).**
- For fixtures whose lockAt falls in the next 30 minutes, list `slatefx:<fixtureId>:*`. That gives the leagues whose published slate holds the fixture.
- Arm one alarm per slot on a new `RevealSlot` Durable Object, keyed by `slotMs`, for `lockAt + 75 s`.
- Re-planning is idempotent: same key, same alarm. A moved kick-off re-arms the alarm, and a stale alarm finds nothing to do.

**2. Confirm (the alarm handler). This is the "server confirms lock" step.** Every check must pass, or nothing is sent:
- (a) The server's own clock is at or after each fixture's lockMs.
- (b) Each fixture's *current* lockAt still equals `slotMs`. If it was rescheduled, re-plan instead.
- (c) `matchLocked()` is true, the same function `savePick` uses, so no further pick can be accepted.
- (d) The fixture is not postponed or void.
- (e) The slate is still published and still lists it (amendments are already refused after lock).

If any read fails, the slot is marked `unconfirmed` and **nothing is sent, ever**: there is no retry past `lockAt + 10 min`. On success it writes a **seal** row in Durable Object SQLite: `slotMs`, the fixture × league pairs, and `sealedAt`. The seal is the confirmation every later step reads.

**3. Fan out.**
- Recipients are members of the sealed leagues (eligible: `since <= lockMs`) whose `push:<uid>` record has `reveal: true` and a token.
- Group by uid, giving one job per player per slot, whatever the number of leagues or fixtures.
- Enqueue on `NOTIFY_QUEUE` with idempotency key `rv:<uid>:<slotMs>`, claimed in NotifyLedger's `delivery` table like reminders.

**4. Send.**
- The consumer re-checks the token, `reveal` still on, and membership.
- Copy: title "N matches kicked off" (N = distinct fixtures across that player's leagues; "1 match kicked off" when single). Body "Picks are locked. See what your mates went for." No picks, scores, names or league names in the alert.
- `apns-collapse-id: po-rv-<slotMs>`, so a duplicate replaces rather than stacks.
- `apns-expiration: sealedAt + 20 min`, so a late alert dies rather than arriving stale.
- Payload: `po:{v:2, k:"reveal", t:slotMs}`. Build ≤35 sees an unknown `v` and opens My Picks.

## P2: Reveal hub, and P3: reveal card

**New endpoint: `GET /reveal-slot?uid=&t=<slotMs>`.**
- **Refuses before lock.** If there is no seal for `t`, or `serverNow < lockMs`, it answers `409 {locked:false}` with no picks, so it never depends on the push having been sent.
- **Membership is re-read on every call.** It returns only fixture × league pairs from the player's current leagues. Content is computed per request and served `private, no-store`.
- **What it returns:**
  - `hub`: a list of `{league, name, fixture}`.
  - Per pair, the card rows: you first, then mates.
  - A pick is shown only when it is valid at lock (`pickValid`, the same as `buildRoundReveal`). An eligible member with no valid pick is returned as `noPick: true`.
  - `more: N` beyond 8 rows.

**Client:**
- `readNotificationRoute` learns `v:2` and returns `{kind:"reveal", t}`. It passes through the Slice 1 router as `followLinkRoute({view:"reveal", t})`, so the same router also serves a `?view=reveal&t=` universal link.
- **On open:** a skeleton first (the Slice 1 component), then `/reveal-slot`.
  - One pair: open its card directly.
  - Several: the "Just kicked off" hub (fixture circles, league name, "See ›").
  - `409` or failure: the Slice 1 failure card wording, never cached picks.
- **Card:** "YOU" pinned first, mates below, "No pick" said plainly, "+ N more mates".
- **Share card:** enabled only after a `200` from `/reveal-slot` in this session; the image is drawn from that response only. The share-card renderer already paginates.

## P4: Settled-week summary

**When it shows:** the round answer (`/state?period`) says `complete`, using the same worker `roundStatus` the lock line uses. There is no settlement event and none is needed: it is derived on open.

**Card at the top of My Picks:**
- "WEEK 13 · SETTLED".
- "+4 pts": the player's row in that round table (server points, not a client recount).
- "1 exact · 1 right result": counted from the Slice 1 `scorePickLocal` outcomes over the week's settled rows. The suite already holds that port to the worker's `scorePick`.

**League movement, "▲ 2 · now 3rd":**
- current = shared rank in the season table.
- previous = shared rank of (season points − this week's points), using the same `sharedRankByUid` that `weeklyMovement` uses.
- This compares the whole settled week, not "minus the last fixture". It needs no worker change and no stored history.
- Shown for the current league only.

Rows below already carry the Slice 1 pick and points line.

## Setting

Profile → Notifications gets a new switch, **"Tell me when mates' picks are revealed"**, subtitle "One alert per kick-off, after picks lock". **Default off.**

- **Stored as** `push:<uid>.reveal` (absent means off). Set through `POST /notification-prefs {uid, reveal}`, the same endpoint that takes `mute`, with an independent field.
- **Consent:** it never reads reminder consent. Turning it on when iOS permission is "prompt" shows the system prompt on that tap.
- **Off is respected server-side** in planning and again in the consumer.
- **Decision needed:** a "Deadline reminders" switch does not exist today. Either add one alongside (a default-on toggle, so current behaviour is unchanged), or keep reminders as they are and add only the reveal switch.

## KV cost per slot

Worked example: one slot of 3 fixtures in 4 leagues of 10 members, with 35 distinct opted-in players.

- **Plan (per cron pass that sees the slot):** 3 `list` calls (`slatefx:`) and 4 slate reads. The fixture pool is already read by the cron. No writes.
- **Confirm and fan out (once):** 4 league reads, 4 member `list` calls plus 40 member reads, and 40 `push:<uid>` reads. About 90 reads, 8 lists, **0 KV writes**. Seal, claims and idempotency live in DO SQLite.
- **Send:** the existing consumer re-check is 1 `push:` read and 1 member read per job (about 70 reads).
- **Each open of the hub:** `user:<uid>`, slates and member lists for that player's leagues, and one `picks:<fixtureId>` per fixture (shared across leagues). About 25 reads for 2 leagues × 10 members × 3 fixtures.

**Total:** roughly 160 reads, 12 lists and no KV writes per slot, plus about 25 reads per open. A Saturday with 4 slots costs about 0.7k reads. That is well under one season `/state` call (932 reads).

## Risks

- **Scheduling.** A 15-minute cron cannot hit "1–2 minutes", so it needs a DO alarm. An alarm that fires late still confirms. Past +10 minutes it sends nothing; a missed alert beats a stale one.
- **KV propagation.** A pick saved seconds before lock may not be visible to the alarm for up to 60 s. The alert carries no picks, and the hub reads on open (minutes later). Pick reads in `/reveal-slot` use the minimum `cacheTtl`.
- **Kick-off moves (TV picks):** confirm checks the live lockAt, re-plans, and a stale alarm no-ops.
- **Postponed or void:** excluded at confirm.
- **Membership churn:** eligibility is by `since <= lockMs` (the reveal's own rule), and is re-read on open.
- **Volume:** a big Saturday 15:00 slot is one push per player, not per league. NotifyLedger's budget applies; collapse-id prevents stacking.
- **Privacy:** the lock-screen text is generic. Picks exist only in the `/reveal-slot` response, after the server's lock check. Sharing is gated on that response.
- **Old builds:** `v:2` falls back to My Picks. The switch exists only in 1.9, so pre-1.9 players never opt in and are never sent one.

## Tests

**Worker:**
- **Confirm refuses:** before lockMs; on a moved kick-off; for postponed or void fixtures; for an unpublished or amended slate; when a read fails. In each case it writes no seal and sends nothing.
- **Exactly one send:** one seal leads to one job per uid, batched across leagues and fixtures. N in the title counts distinct fixtures.
- **Idempotency:** redelivery or retry is one send (ledger claim), and the collapse-id and the 20-minute expiration headers are present.
- **Recipients:** default-off players are not sent anything; switching off between plan and send is honoured.
- **Copy:** the alert has no picks, scores or names, and the payload is `{v:2,k:"reveal",t}`.
- **`/reveal-slot`:**
  - `409` and no picks before the seal or before lock.
  - Non-members get nothing.
  - You first; no-pick members are `noPick`; ineligible late joiners are excluded; `more` above 8.
  - `private, no-store`.
- **KV budget:** a slot of 3 fixtures × 4 leagues × 10 members stays within the counts above. Same instrumented fake KV as the existing budget tests.

**Client:**
- `v:2` routes through the Slice 1 router: one pair opens the card, several open the hub, and `409` or failure shows the failure card. `v:1` behaviour is unchanged, and an unknown `v` falls back.
- Share is disabled until a `200` in this session.
- The card shows "YOU" first, honest "No pick", "+ N more", at 320pt with no wrap.
- **P4:** shown only when the round is `complete`. Points come from the server table. The exact/right-result counts match `scorePickLocal`. The movement test table covers up, down, unchanged, ties (shared rank) and a first week.
- **Setting:** default off, posts `reveal` independently of `mute`, and consent is never reused.

**Simulator:** `simctl push` with a `v:2` payload, tapped from cold and from background, opens the hub or card. Same XCUITest recipe as build 34.
